# Multilingual Customer Support

Open [the review](../index.html#case=global-support&view=summary) or [the intake example](../intake.html?sample=global-support).

An entirely fictional appliance-support desk translates messages into English, then uses a separate AI to triage that translation. Irregular cases enter a shared human queue. Some customers send praise, others report injury, fire or missing-content issues. No real organisation, customer, product or incident is represented.

## Eight traces

| Record | What to inspect |
| --- | --- |
| T001 | Routine thanks, with meaning retained |
| T002 | Spanish injury and emergency-care meaning weakened; routine routing misses the safety team |
| T003 | Wolof language label only; no original or translation; an unassigned weekend queue closes after 48 hours |
| T004 | A fire report reaches duty cover; acceptance and clarification are distinct |
| T005 | A potentially figurative German phrase is clarified with the customer |
| T006 | Embedded instructions stay data; one safety receipt is not general attack resistance |
| T007 | A burnt-smell report and privacy request; unnecessary payload fields despite minimisation policy |
| T008 | Correct translation of a pointer to audio does not acquire the actual request |

Nine source materials, 12 observations, six controls and eight proposed checks retain policy/configuration differences, staffing, original access, incentives, evaluation, pause/recovery and reporting exclusions.

## Construction and limits

All records, model outputs and review notes are hand-authored together. This is an inspectable method/UI rehearsal, not a blind test, independently validated translation set or model benchmark. No model API or real support system is called.

Original French, Spanish, German, Portuguese and English text remains intact in the English edition. Reference meanings are explanations set by the scenario author. The Wolof original and audio are deliberately unavailable; do not invent their contents or label them dangerous.

Times are UTC; observation cutoff is 2026-09-07 08:00 UTC. The 30-minute duty goal and 48-hour timer are invented internal settings, not general or legal requirements. Selected examples cannot estimate error or harm rates. Recommendations are proposed only and need qualified product-safety, language, operational and data-protection review.
